

Informe Final de Trabajo Práctico


    Cambios respecto del diseño original

        Durante el desarrollo no se realizaron modificaciones significativas sobre el diseño conceptual de las clases,
        ya que se buscó respetar la estructura planteada inicialmente. Los principales cambios consistieron en la organización
        del código mediante la creación de paquetes específicos y la reubicación de sus respectivas clases dentro del directorio
        `src`, con el objetivo de lograr una mejor modularización y facilitar el mantenimiento del sistema.
        Se agregaron ArchivoDatos y DatosSistema para poder contar con la persistencia integral de datos en un único TXT, con ArchivoLotes quedando 
        utilizado solo para datos iniciales.
        Además, se incorporó una interfaz gráfica utilizando Java Swing, siguiendo el modelo MVC (Modelo-Vista-Controlador),
        para separar la presentación de la lógica del programa y permitir una interacción más sencilla con el usuario (Main inicia, VentanaPrincipal muestra, ControladorBarrio coordina).+


    Distribución de tareas

        La distribución del trabajo se llevó a cabo de manera dinámica y colaborativa, sin una división estricta o fija de roles.
        Ambos integrantes avanzaron de forma autónoma según su disponibilidad horaria, y se realizaron sesiones de trabajo conjunto
        desde las computadoras de ambos integrantes. En estas instancias, se adoptó una dinámica de programación en la que uno se encargaba
        de la codificación mientras el otro supervisaba, validaba la lógica y verificaba la correcta integración del código.
        También se utilizó GitHub para compartir los avances, mantener actualizado el proyecto y facilitar la integración de las modificaciones
        realizadas por cada integrante.
        Esta forma de organización permitió que ambos participáramos en las distintas partes del sistema y pudiéramos comprender su
        funcionamiento general.


    Dificultades encontradas

        El principal obstáculo al que nos enfrentamos fue la gestión de un volumen elevado de clases y enumerados (Enums).
        Esta complejidad estructural dificultó temporalmente el seguimiento del flujo de información y provocó la aparición de errores imprevistos,
        los cuales requirieron un proceso de depuración y corrección conjunta.
        Otra dificultad fue lograr que las distintas clases se relacionaran correctamente entre sí, especialmente en las funcionalidades que
        involucraban varias operaciones, como la gestión de reclamos, el registro de pagos y las autorizaciones de ingreso.
        También fue necesario prestar especial atención al manejo de archivos, para asegurar que la información registrada se conservara correctamente
        al cerrar y volver a ejecutar el programa.
        Estas dificultades nos permitieron mejorar la organización del código y comprender la importancia de realizar pruebas durante el desarrollo.


    Reflexión del grupo

        A modo de balance, destacamos el desempeño del equipo, caracterizado por una buena comunicación y un trabajo colaborativo constante.
        Esta experiencia nos brindó la oportunidad de afrontar el desarrollo integral de un sistema de software desde sus comienzos, comprendiendo
        y superando los desafíos que implica una implementación de esta magnitud.
        Además, pudimos aplicar en un mismo proyecto distintos conceptos aprendidos durante la materia, como herencia, polimorfismo, encapsulamiento,
        colecciones, manejo de excepciones y patrones de diseño.
        Consideramos que el trabajo nos permitió reforzar nuestros conocimientos de programación orientada a objetos y entender mejor la importancia de
        organizar las responsabilidades de cada clase.
        En conclusión, fue una experiencia positiva que nos ayudó tanto a mejorar nuestras habilidades de programación como a trabajar de manera
        coordinada en un proyecto compartido.
